# STRIDE Part 450 Mission Safety Module

STRIDE is not a licensing shop. This module is an engineering workbook that
hooks Sea Turtle (and, later, other STRIDE trajectory tools) up to the *kinds*
of artifacts people talk about under FAA 14 CFR Part 450: hazards, off-nominal
trajectories, footprints, public-risk bookkeeping, constraints, and an
evidence matrix.

Every report includes:

> STRIDE is an engineering analysis and research tool. Results generated by this module do not constitute FAA approval, a Part 450 license application, or an FAA-validated flight safety analysis.

## What Part 450 is (context, not legal advice)

14 CFR Part 450 is the FAA's launch and reentry licensing rule set. Operators
use it to show they can fly a launch or reentry without exceeding the agency's
flight-safety and public-risk expectations. The actual text lives in the CFR.
STRIDE does **not** ship that text. `regulatory/part450/*.yaml` is a schema
with `PLACEHOLDER` citations so someone can paste the real sections, dates,
and numeric criteria without touching analysis code.

If a threshold has not been filled in from an authoritative source, the UI
prints **REGULATORY VALUE REQUIRED**. We do not hard-code remembered 1e-4 /
1e-6 style limits.

## How the module is structured

Workflow (also the intended swap-in order for higher-fidelity models):

```
Vehicle + CONOPS
  → nominal Sea Turtle trajectory
  → hazard register
  → failure scenarios
  → debris / impact footprint
  → conceptual public risk
  → flight-safety constraints
  → compliance / evidence matrix
  → markdown safety report
```

| Piece | Where | Notes |
| --- | --- | --- |
| Sea Turtle physics | `lib/sea-turtle/` | TS port of `web/js/sim.js` with a real state history (lat/lon/V/γ). |
| Regulatory catalog | `regulatory/part450/` | YAML. Bundled copy in `lib/part450/regulatory/bundledYaml.ts` for the browser; tests fail if they drift. |
| CONOPS / mission | `lib/part450/exampleMission.ts` | Launch vs reentry, sites, stages, FSS flags, timeline. |
| Hazards | `lib/part450/hazards.ts` | Open register. Examples are data, not a closed enum. |
| Failures | `lib/part450/failures.ts` | `FailureScenario` + parameter patches on Sea Turtle. |
| Debris | `lib/part450/debris.ts` | Canned fragments, same ballistic ODEs. Marked conceptual. |
| Geography | `lib/part450/geography.ts` | Synthetic grid or user-provided. No downloads. |
| Risk | `lib/part450/risk.ts` | `Ec = Σ(P_f × P_impact × P_casualty × N)` only. |
| Constraints | `lib/part450/constraints.ts` | Corridor, keep-out polygon, recovery circle. |
| Compliance | `lib/part450/compliance.ts` | JSON-serializable matrix. |
| Report | `lib/part450/report.ts` | The 13-section markdown dump. |
| Dashboard | `app/part450/page.tsx` | Same visual language as Marlin (Plotly, dark panels). |

## What is actually calculated (MVP)

Implemented, first-order:

- No-lift planar entry (`h, V, γ`), exponential atmosphere, inverse-square g
- Nominal targeting so the planar landing longitude hits the recovery aimpoint
- Off-nominal reruns: chute inhibit, Cd scale, entry-angle bias, cross-range rate, mid-flight γ kick
- Optional seeded Cd Monte Carlo (off unless you ask)
- Fragment ballistic falls from a peak-q breakup time
- Haversine impact locations, KE = ½ m V²
- Conceptual Ec sum against a synthetic population grid
- Point-in-polygon keep-out and circular recovery/containment checks
- Compliance JSON + markdown report

## What is conceptual / not calculated

- Anything claiming FAA validation or a license package
- 6-DOF, lifting-body dispersions, winds, GRAM atmospheres
- Real breakup inventories, casualty *areas*, bouncing, skip-recontact
- Aircraft and ship exposure (interface only: `NOT_IMPLEMENTED`)
- Census / LandScan / NFDC airports (don't download them here)
- Flight safety system design, independence, or inhibit analysis
- Numeric public-risk *criteria* until `criteria.yaml` is filled from a cited source
- Authoritative Part 450 requirement text

P_casualty vs kinetic energy in `risk.ts` is a placeholder curve. Replace the
function; don't sprinkle magic numbers through the dashboard.

## Data you would need for a higher-fidelity version

- Vehicle-specific aero tables and a 6-DOF (or at least lifting 3-DOF) propagator
- Validated debris catalog (mass, area, Cd, condition of breakup)
- Population density rasters, airport / airway / maritime traffic, protected areas
- Winds aloft, ship positions, aircraft schedules
- Operator-specific P_f from FMEA / reliability
- An FAA-accepted casualty-area and sheltering model
- Real Part 450 citations, effective dates, and the current public-risk thresholds
- FSS/AFSS rules as executable predicates, not a CONOPS boolean

## Regulatory version control

Edit YAML, not TypeScript, when the CFR moves:

- `regulatory/part450/requirements.yaml` — citations and placeholder text
- `regulatory/part450/criteria.yaml` — numeric thresholds (or `null`)
- `regulatory/part450/applicability.yaml` — launch vs reentry mapping

Every entry is supposed to carry `citation`, `source`, `effective_date`,
`revision`, `verification_date`. The bundled strings in
`lib/part450/regulatory/bundledYaml.ts` must match the files; `tests/part450/regulatory.test.ts`
checks that.

Never put a limit in `risk.ts` "because that's what Part 450 says." Put it in
YAML with a source and a date, or leave it as `REGULATORY VALUE REQUIRED`.

## Replacing a simplified model

Each analysis file is a function over plain objects. To swap debris, for
example:

1. Keep `DebrisFragment` / `DebrisFootprint`.
2. Write `propagateFragment` against a new propagator (or call an external code).
3. Pass the new footprint into `assessPublicRisk` / the report.
4. Leave the YAML catalog alone.

Same idea for geography (`GeographicDataset`), failures (`FailureScenario.parameterChanges`
is a bag of knobs), and constraints (add a `kind` and a branch in
`evaluateConstraints`).

## Example mission

`leoReusableReentryMission()` is a capsule-class LEO return toward a synthetic
Florida recovery site. Run it from the `/part450` dashboard or:

```ts
import { runMissionSafetyAssessment, generateSafetyReport } from "@/lib/part450";

const assessment = runMissionSafetyAssessment();
console.log(generateSafetyReport(assessment));
```

The static Sea Turtle lab in `web/` is unchanged. The TS library is the copy
Part 450 uses so we can keep a full ground track.
